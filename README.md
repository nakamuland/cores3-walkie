# CoreS3 Walkie

M5Stack CoreS3を2台使う、Wi-Fi内で動作する簡易トランシーバーの試作です。タッチ操作で音声を送受信し、静止画も相手に送れます。

## できること

- 画面左のボタンを押している間、音声を送信（PTT方式）
- 画面右のボタンで写真を撮り、相手の画面に表示
- 画面右上にバッテリー残量を表示
- カメラを上にして持てるよう、画面と送信写真を180度回転
- 画像・音声は端末間のWi-Fi接続内で送受信し、クラウドには送信しない

## 必要なもの

- M5Stack CoreS3 2台
- Arduino IDE
- M5Stackボードマネージャ 3.2.2以上
- M5Unified 0.2.22以上、M5GFX

M5Unified 0.2.22では、このスケッチが使うマイク／スピーカーのバッファ解放コールバックが追加されています。最新版の利用を推奨します。参考：[M5Unified 0.2.22リリース](https://github.com/m5stack/M5Unified/releases/tag/0.2.22)、[CoreS3マイク](https://docs.m5stack.com/en/arduino/m5cores3/mic)、[M5Unified Mic_Class.hpp](https://github.com/m5stack/M5Unified/blob/master/src/utility/Mic_Class.hpp)。

## 書き込み

1. `cores3_walkie.ino` と `walkie_config.h` を同じフォルダーに置き、Arduino IDEでスケッチを開きます。ボードに **M5CoreS3** を選択してください。
2. `walkie_config.h` の `WIFI_SSID`、`WIFI_PASSWORD`、必要なら `WIFI_CHANNEL` を設定します。パスワードは両方の端末で同じものを使い、8文字以上の独自の値にしてください。サンプルの値をそのまま使わないでください。
3. 1台目は `DEVICE_IS_AP = true` のまま書き込みます。この端末がWi-Fiアクセスポイントになります。
4. 2台目は `DEVICE_IS_AP = false` に変更して書き込みます。SSIDとパスワードは1台目と同じにします。
5. 2台を起動します。接続待ちが表示された場合は、接続が完了するまで数秒待ってください。シリアルモニターは115200 baudです。

## 操作

- **HOLD TO TALK**：左側を押している間だけ送話します。離すと受信に戻ります。
- **SEND PHOTO**：右側をタップして静止画を撮影し、相手へ送ります。

表示や操作ラベルは英語です。撮影写真と画面は、カメラ側を上にして持ちやすい向きに180度回転しています。バッテリー残量は30秒ごとに読み取り、残量が変わったときに表示を更新します。

## 通信の概要

- 音声：16 kHz、16-bit、モノラルPCMを20 msごとにUDP送信。パケットロス時の再送はありません。
- 写真：QVGA（320×240）のRGB565フレームを端末内でJPEGに変換し、TCPで転送します。GC0308からJPEGを直接取得する方式ではありません（参考：[esp32-camera](https://github.com/espressif/esp32-camera)）。
- AP側は `192.168.4.1`、クライアント側は `192.168.4.2` を使用します。
- 通信形式のメモは [`PROTOCOL.md`](PROTOCOL.md) を参照してください。

## 制限と安全上の注意

- 写真の撮影・転送中はメインループが転送処理を行うため、音声が一時的に止まります。まずは片方ずつ送話してください。
- 同時送話の衝突制御、音声コーデック、ジッターバッファ、写真保存機能はありません。
- このプロジェクトは実験用のスターターです。アプリケーション層の暗号化・認証や堅牢なネットワーク保護は実装していません。独自のWi-Fiパスワードを設定し、信頼できる環境で使用してください。
- `walkie_config.h` に含まれるSSIDとパスワードはサンプルです。公開リポジトリに実際のネットワーク認証情報を追加しないでください。

## ファイル

- `cores3_walkie.ino` — 音声・写真転送、カメラ、タッチ画面の本体
- `walkie_config.h` — AP／クライアントの切替とWi-Fi設定
- `PROTOCOL.md` — 通信形式のメモ
